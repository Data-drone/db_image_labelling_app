# Image Labelling App Roadmap

**Created:** 2026-04-27
**Status:** Proposed

---

## Current State

The app is a functional MVP deployed as a Databricks App. It supports:

- Project creation pointing at UC Volumes as image sources
- Single-class **classification** labelling with keyboard shortcuts
- **Bounding box detection** labelling via an interactive canvas
- Sample navigation via scrubber with deep-link support
- Gallery view with status filtering (all / labeled / unlabeled / skipped)
- Export to **COCO JSON** (detection) and **CSV** (classification) on a target UC Volume
- Project cloning (versioning with copied samples, empty annotations)
- Identity from Databricks Apps SSO headers (no in-app roles or permissions)
- Lakebase (managed Postgres) as primary database with SQLite fallback

---

## Phase 2 — Quality of Life

Highest impact, lowest effort. Addresses daily friction for labellers.

### 2.1 Undo / Correction Workflow

Allow labellers to revisit and re-label any sample. Show edit history so reviewers can see what changed and when.

### 2.2 Keyboard-Driven Workflow for Detection

Extend keyboard shortcuts to detection: hotkeys for selecting the active class, confirm/cancel a box, navigate to the next image, and undo the last box.

### 2.3 Multi-Label Classification

Support selecting multiple classes per image for tasks that require it (e.g., "outdoor", "daytime", "contains vehicle").

### 2.4 Progress Dashboard

Per-project view showing:
- Total samples, labelled / unlabeled / skipped counts
- Labels per class (bar chart)
- Labelling velocity over time
- Estimated time to completion

### 2.5 Search & Filter in Gallery

Filter samples by class label, filename, or labeller. Enables auditing specific subsets (e.g., "show me everything labelled 'defective'").

## Phase 3 — Collaboration & Data Quality

Support multiple concurrent labellers with quality controls.

### 3.1 Collaborative Locking

The backend has a lock-on-open endpoint (`/next`), but the frontend scrubber bypasses it. Wire up proper locking so two labellers never annotate the same image simultaneously.

### 3.2 Labeller Assignment & Workload Splitting

Assign subsets of images to specific labellers so work is evenly distributed without overlap.

### 3.3 Inter-Annotator Agreement / Review Mode

Have 2+ people label the same images independently, then surface disagreements for a reviewer to adjudicate. Standard approach for ensuring label quality.

### 3.4 Role-Based Access

Distinguish between:
- **Labeller** — can only label assigned images
- **Reviewer** — can approve/reject labels
- **Project Owner** — can create/configure/export projects

Prevents accidental project deletion or misconfiguration.

### 3.5 Comments / Flags on Samples

Let labellers flag ambiguous images with a note (e.g., "blurry, can't tell if cat or dog") so a reviewer can handle edge cases.

---

## Phase 4 — Annotation Capabilities

Expand the types of labels the app supports.

### 4.1 Polygon / Freeform Segmentation

For use cases where bounding boxes aren't precise enough (e.g., medical imaging, satellite imagery, irregular shapes).

### 4.2 Keypoint Annotation

For pose estimation or landmark detection (e.g., facial landmarks, body joints).

### 4.3 Image-Level Attributes / Metadata

Beyond class labels, attach structured metadata: quality score, weather conditions, camera angle, etc.

### 4.4 Model-Assisted Labelling (Pre-Labels)

Run a model (e.g., from Databricks Model Serving) on unlabeled images to generate draft labels, then have humans review and correct. Can 3–5x labelling throughput.

### 4.5 Recursive Volume Scanning

Currently only one directory level is scanned. Support nested folder structures so large image datasets don't need to be flattened.

---

## Phase 5 — Import, Export & Integration

Smooth data flow in and out of the app.

### 5.1 Import Existing Labels

Load annotations from COCO JSON, Pascal VOC XML, YOLO txt, or CSV so partially-annotated datasets can be continued.

### 5.2 YOLO Export Format

The export design doc mentioned YOLO but it isn't implemented. YOLO is the most common training format for detection models.

### 5.3 Delta / Lakehouse Sync as First-Class Export

Sync annotation tables directly to Delta Lake so downstream ML pipelines can read labels without a manual export step.

### 5.4 Webhook / Notification on Project Completion

Trigger a Databricks job or send a notification when all images in a project are labelled, closing the loop to model training.

---

## Phase 6 — Scale & Advanced UX

For larger teams and datasets.

### 6.1 Active Learning Loop

Integrate with Model Serving to prioritize labelling images where the model is least confident, maximizing the value of each label.

### 6.2 Batch Operations

Select multiple images in the gallery and apply a label, skip, or delete in bulk.

### 6.3 Video Frame Extraction

Point at a volume of videos, extract frames at configurable intervals, and label them as images.

### 6.4 Dark Mode / Accessibility

Reduce eye strain with a dark theme. Ensure the app is fully keyboard-navigable and screen-reader friendly.

### 6.5 Audit Log

Full history of who labelled what, when, and any changes. Required for regulated industries (medical, automotive).
